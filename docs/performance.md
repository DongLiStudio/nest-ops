# 控制台性能与刷新行为

主快照、家庭状态与单服务曲线是独立的认证只读请求。主页可以先展示目录和监测状态，不必等待 UPS/DDNS 接口；进入服务详情后再加载近 24 小时曲线。

## 缓存与数据时效

- 主快照按四种统计窗口分别缓存，最多 5 秒；SQLite 写入后按数据库修订立即失效，同一时间的重复计算串行合并。
- UPS/DDNS 两个上游请求并行，每项保留 2 秒超时，成功或失败结果最多缓存 10 秒；失败清空对应指标，不把旧的在线状态当最新结果。
- 单服务曲线只查询指定服务的近 24 小时样本，前端缓存最多 30 秒，并复用正在进行的同服务请求。
- 所有 HTTP 请求仍逐次验证登录会话；响应保持 `Cache-Control: no-store`。服务端内存缓存不替代认证。
- 客户端支持 gzip 时，超过 1KB 的响应使用 gzip；未声明或禁用 gzip 的客户端收到普通响应。

后台轮询对比并复用未变化的 DOM 子树，更新变化的文本和区域；依赖事件闭包的交互组件整体替换，避免保留旧回调。事件分页面板保持原实例，不因其他状态刷新被清空。时间范围切换会取消旧快照请求，并以请求序号拒绝乱序响应。

## 验证

```sh
python console/tests.py
node scripts/test_ui.cjs
node scripts/test_event_loading.cjs
node scripts/test_loading.cjs
python scripts/preview.py
# 浏览器打开 http://127.0.0.1:18765/test-reconcile
```

`test-reconcile` 在真实浏览器 DOM 上验证节点复用、变化文本、交互回调和事件面板保留；不是生产服务测试。

可运行 `python scripts/benchmark_console.py` 复现合成快照基准。该脚本比较历史提交 `a680e23` 与当前源码，因此本地需要保留该提交的 Git 历史。

一次本机测试：67 项合成服务、19,296 条样本，两个家庭接口各模拟 80ms 等待。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首次快照计算 | 197.7ms | 12.1ms |
| 连续重复调用中位数 | 197.1ms | 0.001ms（缓存命中） |
| 未压缩 JSON | 999,183 字节 | 606,925 字节 |
| gzip 后数据量 | 18,919 字节 | 7,938 字节 |

这些数字只用于检查计算和载荷变化，不包含认证、网络、TLS、浏览器渲染和真实用户交互延迟。生产端是否更快，仍需用真实环境验证；不以合成数据宣称固定加速比例或“绝对最优”。
